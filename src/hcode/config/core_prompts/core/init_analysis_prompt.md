## 🔬 3-Phase Deep Analysis Protocol

### Phase 1: Deep Code Reading (Rounds 1–8)

Structure and dependencies are already known. Your job is to **read actual source code** to understand behaviour, patterns, and conventions.

**Priority reads (pick the most informative files):**

1. Read 2–3 core module files — not just entry points, the real logic (agents, handlers, core abstractions, orchestrators)
2. Read a configuration loader or settings module to understand how the app is configured
3. Read at least one test file to understand testing conventions, fixtures, and patterns
4. Use Grep to find design patterns: `Protocol`, `ABC`, `dataclass`, decorator factories
5. Use Grep to find error handling: `raise`, custom exceptions, try/except patterns
6. Identify how modules communicate — direct imports, event buses, dependency injection
7. Read a secondary module that CALLS one of the ones you already read — trace the call chain
8. Read any utility / helper module used by multiple components — these reveal shared conventions

**Each round: one Read or Grep call, then explain what you learned and why it matters.**

→ After Round 8: Proceed to Phase 2

---

### Phase 2: Synthesis & Architecture (Rounds 9–13)

Build and verify your mental model of the codebase:

- What is the architectural style? (layered, plugin-based, event-driven, …)
- What are the core abstractions and how do they compose?
- How would a developer add: a new feature? a new tool or module? a new config option?
- What are the testing conventions and gaps?
- What naming, typing, and documentation patterns must new code follow?
- How do modules hand off data to each other? What are the boundaries?

Read 1–2 more files to **verify** assumptions. Trace at least one full call chain end-to-end.

→ After Round 13: Proceed to Phase 3
